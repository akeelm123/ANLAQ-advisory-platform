# v0.9.2-alpha.1 — persistent local pilot candidate
Owner selection and approval of local Option A are recorded in LOCAL-ARCHITECTURE-APPROVAL.json against the architecture commit. Local application launcher is executable and ready for first-run named fictional-account setup. No actual vault or user credentials were created, and no service is left running by tests.

## Delivered
- Single-instance owner-only local vault, passphrase-derived independent encryption, evidence and audit keys, random salt, in-memory SQLite and encrypted complete-image checkpoint. No plaintext persistent SQLite file for this mode. Atomic durable image replacement before success acknowledgement; fail closed on checkpoint error. Current image and salt private file modes; lock prevents concurrent normal launches.
- Separate named accounts on bootstrap, no shared passwords, no credentials printed or stored in repo. Fresh sign-in after restart, revoked memberships preserved. Owner-only confirmed revocation action; no automatic reset/re-enrolment.
- Loopback-only local server; scoring/model modes default and remain disabled; no cloud. Optional offline archive and verified recovery into new empty vault. Archive expiry is a synthetic test cap, not deletion. Source/audit and methodology checks on restore.
- Existing ephemeral demo still available; persistent mode is separate. UI identifies mode and role status. No external access or public release.

## Remaining operational gates
No actual user vault initialized, FileVault or RAM not verified, separate OS accounts/physical independent reviewers unverified, active scanner isolation and production identity not implemented; no approved retention/deletion, external audit or anti-rollback mechanism. Local owner can control the device and substitute valid backups; no protection against malicious same-OS account. Single machine availability, rolling 30-day max synthetic archive expiry and 32 MiB limit are candidate constraints. No automated classification of real data. No durable record of unsuccessful requests guaranteed; checkpoint failure returns failure and blocks further operations, inspect durable state before retry. No production or real-client processing, no cloud, no score calibration approval. Independent machine and synthetic cohort operational acceptance remains outstanding; see LOCAL-PILOT-START.md.
