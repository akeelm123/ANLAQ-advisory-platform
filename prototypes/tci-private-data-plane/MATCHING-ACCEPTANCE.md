# v0.9.3-alpha.1 — intelligent evidence matching candidate
Owner agreed to add intelligent evidence matching after inspecting the zero-supported Aurora workbook dry run. This release adds discovery, not automated adjudication. Synthetic-only, local loopback, no client data, production scoring or deployment.

## Delivered
- Criterion, optional exact stakeholder claim and optional search focus. Search latest accepted current documents across the assessment, with criterion fields/intent, weighted word overlap, small explicit domain synonym groups and approved mapping priority. Ranked relevance is not confidence. Source format parsing uses existing TXT/PDF/DOCX/XLSX parsers; exact source quote, locator, original context, owner, period and SHA-256 retained. Ranked retrieval is heuristic rather than embedding/vector semantic search.
- Distinguish no accepted documents from no retrieved passages. Bound scan to 40 sources, 400 passages per source, 4,000 total segments and 24 displayed candidates; show bounded/unparsed warnings. Relevant unmapped documents are discovery-only, cannot silently amend methodology, cannot be confirmed into validation.
- Possible numeric difference, negative/missing context, actual-versus-target/forecast hints are review aids, not contradictions. Source wording, metric definition, unit, period and population require human review.
- Optional existing fixed-loopback model gpt-oss:20b labels up to eight retrieved candidate IDs as potential support/conflict, context-only, irrelevant or uncertain; never generates citation text. Strict schema and ID validation; one retry only for omitted candidate IDs, partial/unavailable explicitly labelled; ranked results retained without external fallback. Persistent local launcher keeps model off by default and in its current candidate mode; optional semantic labels available in explicitly enabled ephemeral synthetic demo. No external provider.
- Immutable encrypted discovery and relevance decision records, assessor preview of full accepted source before explicit link/reject, mapped current exact source rechecked. Confirmed candidate can be selected in criterion validation draft without retyping quote; linked claim must agree; independent validation review still required. Stale evidence invalidates link reuse. Contributor excluded. No automatic evidence grade, condition, contradiction resolution, score or decision.
- Upgrade from v0.9.2 encrypted checkpoint verifies old image, adds only new matching schema, preserves source and audit records, and checkpoints next successful operation. Test old-layout synthetic archive only; no actual user vault accessed.

## Verification
Nine focused matching tests cover seven-dimension narrative benchmark (correct primary passage ranked first in all seven synthetic cases), no-source vs no-relevance, potential numeric discrepancy, unmapped/stale link guards, human preview/confirmation, linked claim requirement, candidate trace into independently reviewed validation, role/tenant restrictions, local label schema/fallback, missing-ID retry and seeded mock preview without adjudication. Installed local model digest recorded: first three-passage attempt labelled support/conflict but omitted context-only target; prompt/one-retry coverage improvement rerun produced all 3 expected labels. A tiny synthetic label check, not a representative semantic accuracy benchmark. 266 service tests (including old encrypted checkpoint migration), 16 API tests and two browser workflows passed. Matching browser verifies exact source selection, rejected confirmation before preview, confirmed candidate into draft, separate reviewer acceptance, locked score, role isolation. Local persistence regression passed. See MATCHING-LOCAL-MODEL-RESULT.json and test result logs.

## Live preview / limits
Separate fictional demonstration has one 80% adoption assertion, two mapped 70% actual-usage documents, one 90% later target, four ranked candidate passages and zero automatic validated findings. Original Aurora source-only and document-backed demo untouched. Launch validation_demo.py --matching-preview --enable-local-model --port <unused-local-port> for optional synthetic local model labels. No claim that all relevant documents/passages are retrieved, no OCR/embedding recall or real-world semantic calibration acceptance. Search is user-initiated per criterion/claim; no autonomous decision workflow. Operational local machine assurance and real-data authorisation remain locked.
